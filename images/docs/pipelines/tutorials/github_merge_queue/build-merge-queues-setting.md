# Build merge queues

Recreate the settings screenshot for [Enable merge queue builds for a pipeline](/docs/pipelines/tutorials/github-merge-queue#enable-merge-queue-builds-for-a-pipeline), following the [shared screenshot guidance](../../../../../styleguides/working-with-docs-site.md#screenshots).

Use a dedicated test organization and an existing GitHub-linked Buildkite Pipelines pipeline with permission to manage pipeline settings. Use a fixture with **Trigger builds after pushing code** selected, **Build merge queues** initially clear, and its subordinate settings clear. No installation changes, webhook changes, or builds are needed.

1. In **Pipelines**, open the pipeline and select **Settings** in its pipeline tabs, then **GitHub**. Under **GitHub Settings**, find **Trigger builds after pushing code** and expand **Merge queue checks**.
1. Select the real **Build merge queues** checkbox without saving. Verify that the checkbox is selected and the **GitHub merge group events required** callout is visible. This shows the selection step, not a saved setup or a configured webhook. Do not change the other controls. Navigate away without saving after each capture. Reopen the form and verify that the checkbox is clear again.
1. Use Chromium on macOS with its native system typography. Use a 1040 × 720 CSS-pixel viewport, 100% zoom, and pixel density two. Wait for `document.fonts.ready`. Verify that the label and help text render in the native system font (reported as `.SF NS` by Chromium), with Monaco for inline code.
1. Position the top of the expanded disclosure at about y=100 CSS pixels. Crop to its full width and height and retain its native padding and a little surrounding background. The reference crop starts at (316, 93) and measures 667 × 550 CSS pixels. Keep the disclosure title, selected box, full description, webhook callout, and subordinate controls with their help text. Crop out adjacent disclosures, save buttons, navigation, and identifying or sensitive fields. Do not hide any elements or add a frame, shadow, or annotations.
1. Capture `build-merge-queues-setting.png` in light mode and `build-merge-queues-setting-dark.png` in dark mode. Use Buildkite's **System** appearance with browser color-scheme emulation (`set media light`, then `set media dark`). Set the preference before fresh navigation and verify the actual product theme. Repeat the unsaved selection with the same viewport, zoom, scroll position, crop, and resulting form state.

Accept two 1334 × 1100 PNGs with identical content and geometry, intended to display at 667 × 550 CSS pixels. Keep the checked box and webhook requirement easy to find and the bottom callout fully visible with breathing room below it. Exclude the pointer, hover or focus styling, and any account or repository identity.
