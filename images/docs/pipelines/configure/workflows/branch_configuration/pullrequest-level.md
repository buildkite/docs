# Additional branch filtering for pull request builds

Recreate the [additional branch filtering for pull request builds](/docs/pipelines/configure/workflows/branch-configuration#additional-branch-filtering-for-pull-request-builds) example, following the [shared screenshot guidance](../../../../../../styleguides/working-with-docs-site.md#screenshots).

Use an existing GitHub-linked pipeline in a development or dedicated integration-test organization. You need permission to manage the pipeline and a fixture with **Trigger builds after pushing code** already selected. Do not save settings, change GitHub configuration, deliver webhooks or create builds.

1. Use Chrome for Testing 158 on macOS 27.2 with a 1150 × 1450 CSS-pixel viewport, 100% zoom, and DPR 2. Start in macOS Light with Chrome's `prefers-color-scheme` set to `light`. Verify native Light rendering, wait for `document.fonts.ready`, and verify `.SF NS` for the UI and Monaco for inline code.
1. Open pipeline **Settings → GitHub**. In **GitHub Settings**, verify the selected push trigger and note the saved pull request trigger, filter checkbox, and branch pattern. Collapse **Branches and tags** and expand **Build on pull request activity** with their native controls. Select **Build when pull request is opened or updated**. Under **Pull request webhook options**, select **Limit pull request branches** and enter `features/*`. Leave all changes unsaved and keep other events and options in their existing states.
1. Position the complete expanded **Build on pull request activity** accordion in view. Move the pointer outside the crop and clear input focus by clicking blank page space. At scroll (0, 1581), crop the viewport from (361, 127), 672 × 1131 CSS pixels. If the layout changes, measure the full accordion border and leave about 8 CSS pixels of surrounding space. Keep all rows within the border, including the events and webhook options between the two controls. Do not edit the page or include surrounding panels or navigation.
1. Convert the crop to sRGB without resampling and save `pullrequest-level.png`. Leave without saving and reopen **GitHub** to compare the saved trigger, checkboxes and branch pattern with their starting values. Repeat from fresh navigation in macOS Dark with Chrome's `prefers-color-scheme` set to `dark`. Verify native Dark rendering, save `pullrequest-level-dark.png`, and repeat the saved-state check.

Accept two sRGB PNGs at 1344 × 2262 pixels, displayed at up to 672 × 1131 CSS pixels. Both show the full expanded accordion, the selected pull request event and its note about pipeline-level branch filters, and the selected branch filter with `features/*`. Use identical geometry. No recoloring, callouts, browser chrome, clipping or identity.
