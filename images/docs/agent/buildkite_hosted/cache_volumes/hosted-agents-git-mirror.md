# Enable Git mirror

Recreate the setting shown in [Enabling Git mirror volumes](/docs/agent/buildkite-hosted/cache-volumes#git-mirror-volumes-enabling-git-mirror-volumes), following the [shared screenshot guidance](../../../../../styleguides/working-with-docs-site.md#screenshots).

Use an existing cluster with hosted queues in a dedicated integration test organization. You need permission to manage the cluster's cache settings. No builds, provisioning, or saved changes are needed.

1. Use Chrome for Testing 158 on macOS with a 1000 × 720 CSS-pixel viewport, 100% zoom, and pixel density two. Use **System** appearance, set browser color-scheme emulation to light, and verify the product renders in light mode. Wait for `document.fonts.ready` and verify the actual rendered heading, labels, and help text use the native system font (`.SF NS` in Chromium).
1. Select **Agents** > your cluster > **Cached Storage** > **Settings**. Note both saved checkbox values. The screenshot shows **Enable Git mirror** checked and **Enable container caching** clear. Use the actual controls to reach that state without saving; leave any already matching control as it is. Verify the full mirror help text: “Speed up Git checkouts by creating a local mirror for each Git repository.” If the UI differs, report the difference rather than editing the text.
1. At scroll y=0, crop the viewport from (22, 105) at 956 × 467 CSS pixels. Include the selected **Cached Storage** sidebar destination and page heading, **Volumes** and **Settings** tabs with **Settings** selected, and the entire **Hosted Queue Cache** panel with both controls, their complete help, and **Save cache settings**. Stop just below the selected sidebar row. Use a generic cluster name safe to show; crop out global account navigation and browser chrome. Do not hide or restyle elements. Move the pointer off the subject and clear focus styling.
